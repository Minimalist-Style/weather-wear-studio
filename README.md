# Weather & Wear Studio

Готовый исходный проект для научной работы «The Weather Station & Clothes Guide» (Маратова Аяжан, Мақсат Ақжібек; руководители — Хисабек Жәния Хисабекқызы и Калдыбаева Динара Бериколовна). Основа исследований — документы заказчицы; данные наблюдений и результаты опроса **не выдуманы**.

## Что реализовано

- Авторский адаптивный интерфейс, переключение казахского и английского языков.
- Погодный прогноз Open-Meteo, поиск городов Казахстана, прогноз на три дня.
- Рекомендации одежды на основании температурной матрицы проекта; ветер и осадки меняют совет. Это образовательная подсказка, не рекомендация по здоровью или безопасности.
- Интерактивные сценарии погоды, отдельная маркировка симуляции.
- Личный дневник наблюдений в `localStorage` браузера с ручным вводом температуры, ветра и комфорта; экспорт CSV для анализа. Дневник сохраняется **только в том браузере, где его заполнили**. CSV с заметками может содержать личные данные — не публикуйте его без согласия.
- Тесты базовых правил подбора одежды (Vitest).

## Запуск на Mac в Google Antigravity / терминале

1. Установите актуальную версию Node.js, подходящую для Vite (рекомендуется Node 22.12+ или 24+). Проверьте: `node -v` и `npm -v`.
2. Распакуйте архив. Откройте папку `weather-wear-studio` как проект в Antigravity.
3. В терминале этой папки выполните `npm install`.
4. Выполните `npm run dev`, затем откройте локальный адрес, который покажет терминал (обычно `http://localhost:5173`).
5. Проверьте `npm test` и `npm run build`. Итоговые файлы сайта окажутся в `dist/`.
6. Перед размещением проверьте на iPhone/Android, что рекомендации и язык переключаются, а дневник записывает и выгружает CSV.

`npm install` нужен один раз и требует интернет; `npm run dev`/`build` работают на вашем компьютере. Для работы прогноза на странице нужен интернет. Для демонстрации без прогноза выберите сценарий в лаборатории — он не выдаётся за реальные метеоданные. Не открывайте исходный `index.html` двойным нажатием: сначала запустите dev-сервер или соберите `dist`.

## Развёртывание

**Netlify:** отправьте проект в GitHub (не включайте `node_modules`, `dist` или секреты), затем в Netlify выберите Import from Git. Сборка `npm run build`, директория публикации `dist`. В проекте есть `netlify.toml`. Другой путь — выполнить `npm run build` и загрузить *содержимое* `dist` как статический сайт на хостинг. Не загружайте папку с TypeScript-исходниками без сборки.

**Google:** для хостинга статического сайта можно использовать Firebase Hosting. Инициализируйте его в папке проекта; укажите public directory `dist` и выполните `npm run build` перед публикацией. Не включайте серверные функции без необходимости. Ни Netlify, ни Firebase не превращают веб-сайт автоматически в бинарные приложения App Store/Google Play — это отдельная задача.

## Архитектура

- `src/App.tsx`: интерфейс, состояния, дневник и взаимодействия.
- `src/recommend.ts`: независимые правила рекомендаций; в дальнейшем можно вынести в общий пакет для веб- и мобильной версии.
- `src/weather.ts`: отдельный адаптер погодного API и геокодирования; его можно заменить без переписывания логики одежды.
- `src/diary.ts`: локальное сохранение и CSV; при росте проекта заменить серверной базой с согласиями, доступами и защитой детских данных.
- `src/recommend.test.ts`: проверка основных веток рекомендаций.

## Правовые и продуктовые ограничения

Open-Meteo Free API допускает некоммерческие образовательные сценарии, но **не** коммерческий продукт. Перед коммерческой публикацией уточните условия лицензирования и получите соответствующий тариф/другого поставщика. Укажите атрибуцию поставщика. В этой версии нет API-ключей: не кладите платный ключ в `src`, публичные переменные `VITE_` или GitHub. Для платного API нужен серверный proxy/функция с секретом на сервере.

Данные Open-Meteo — численная модель погоды, а не прямые измерения сделанной детьми метеостанции. Исследовательские результаты должны появиться после реальных наблюдений и опроса. Нет аккаунтов, push-уведомлений, автоматической синхронизации устройств и публикации в магазинах. Код подготовлен как расширяемый прототип, но не испытан под нагрузкой или в браузере конечного устройства.
